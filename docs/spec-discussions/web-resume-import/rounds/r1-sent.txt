## 規則（違反就等於沒做）

1. **只討論，不要動手。** 不要改任何檔案，不要跑測試、build、lint、npm script、安裝、登入，也不要呼叫任何模型或連網服務。可以讀檔、搜尋、算 sha256（例如 rg、sed、cat、shasum）。repo 根目錄的 `AGENTS.md`／`CLAUDE.md` 若講實作流程，這一輪不適用。
2. **講程式行為要有出處。** 指出檔名與行號，或貼出你讀到的那幾行；講規則要指出是哪份 spec 的哪一節或編號。
   「我覺得可能會…」沒有出處的，標成 `assumption`，不要混進 finding。
   **外部事實**（104／Cake／Yourator 的條款與頁面 DOM、Chrome 擴充功能 API 的實際行為、Chrome 產生 PDF 時如何嵌入圖片等）你無法在本機查證的，一律標 `assumption`，不能當 blocker 的唯一依據。
3. **分三類，每一項都要標：**
   - `blocker`：照這樣寫下去會壞、會自相矛盾、會和現行程式或 `docs/specs/` 衝突、會有資料／隱私／權限問題，或驗收條件無法判定。
   - `needs_owner`：這是產品取捨，不是技術問題，要人決定。列出選項與各自代價。
   - `optional`：可以更好，但不擋。**最多三項**，不要把範圍撐大。
4. **不要重寫規格。** 指出問題就好，不要附上你版本的完整規格。
