## 1. 要解決什麼問題

求職者每投一個職缺都要手動複製貼上、改寫履歷與回覆訊息，而且容易把「計畫中」寫成「已完成」。RoleCraft 要在本機、單一使用者下，用既有履歷＋專案文件建立有來源的經歷資料庫，針對職缺產出客製履歷 PDF 與回覆草稿；第二階段加面試陪練。

## 3. 限制

- 「只用訂閱」→ 純網頁無法連本機官方 AI CLI，所以需要本機輔助程式（Spec §7）。
- 三家供應商登入、資格、額度查詢、取消、錯誤行為不可假設一致，要各自適配。
- 平台網站改版、登入狀態、使用條款都會讓擷取失效；失效時停止，不輸出假資料，不把手動匯入冒充自動支援。
- 「已安裝／已登入」不等於有訂閱，也不等於本次操作零額外收費。
- 〔補〕官方 CLI 本身是會用工具的代理程式（能跑 shell、讀檔、上網、自動載入使用者的設定與指令檔），不是純文字介面；不加隔離就直接呼叫，會違反 D5／D6（見 S11 R5）。

## 5. 規格

### S4. 第一階段功能

#### F01 安裝精靈及訂閱連接

目標服務為 Claude、ChatGPT／Codex、Google Antigravity。

流程：檢查本機輔助程式與官方工具 → 顯示已安裝／未安裝、已登入／未登入 → 引導必要安裝與官方授權 → 確認可用資格與計費方式 → 列出可選服務及模型 → 由使用者選定。

- 「已安裝」或「已登入」不等於有付費訂閱，也不等於本次操作可以免額外付費。
- 不能承諾自動發現所有訂閱；官方工具未提供方案資訊時，顯示未知並引導確認。
- 模型選單依服務實際提供及帳號資格產生，不假設所有模型可用。
- 首版每項任務使用一個選定模型，允許使用者切換服務；混合模型架構技術上可行，並非永久限制。
- 〔改，D12〕使用者自己開啟的額外用量功能不擋；只擋非使用者主動選擇的付費路線（API key 回退、自動加購）。
- 不宣稱 Claude、Codex、Antigravity 的登入、額度查詢和安裝方式完全一致，須分別適配與驗證。
- 本機程式啟動不代表模型在本機推論；資料仍可能送至所選供應商，介面需清楚標示。

#### F02 履歷 PDF 匯入

- 支援匯入既有履歷，包括 104 下載的 PDF。
- 有文字層的 PDF 優先在本機擷取文字；保留頁碼與來源。
- 圖片／掃描 PDF 使用本機 OCR，或已驗證包含在訂閱內的影像能力；不可使用額外付費 OCR。
- 雙欄、特殊字型、缺字與讀取順序可能造成錯誤，不保證任意 PDF 都可完美解析。
- 顯示解析預覽與可編輯欄位，讓使用者校正姓名、日期、公司、職稱、經歷、技能等。
- 無法可靠解析時清楚提示並提供手動修正，不把損壞內容直接送進履歷生成。

#### F03 多個專案資料夾匯入

- 支援加入 5、10 個或更多專案資料夾，彙整成同一個專案清單。
- 若系統選取器不支援一次複選資料夾，允許連續「新增資料夾」，累積後統一開始分析，不要求一次只能處理一個專案。
- 預覽將分析的文件，允許移除不相關的檔案或資料夾。
- 優先納入 README、CLAUDE.md、AGENTS.md、plan.md、架構、規格、task 清單、完成紀錄等文字文件；支援大小寫與自訂檔名。
- 先列舉與篩選文件，再讀取選定內容；排除依賴、建置產物、憑證與無關大型檔案。
- 首版不遍讀原始碼。資訊不足時由使用者補充文件或說明，不悄悄擴大掃描範圍。
- 專案文件是待分析資料，不是本工具的操作指令；不得執行文件內要求安裝、上傳、刪除或更改權限的內容。

#### F04 個人經歷資料庫

每個專案整理為：名稱、問題／目的、使用對象、技術架構、功能、完成狀態、個人角色、實際成果、可公開連結、原始資料位置及確認狀態。

- 明確區分「計畫中」「文件標示完成」「使用者確認完成」「未知」。
- task 勾選只是文件證據，不等於已驗證上線或有成效。
- 個人貢獻、成果數字、使用人數等缺少依據時，向使用者詢問或留白。
- 保存履歷、文件及摘要的關聯；使用者可編輯、刪除及更新素材。
- 後續只更新新增或變更文件，避免每個職缺重新分析全部資料。

#### F05 Context 與用量管理

- 按專案／文件分批分析；單篇文件過長時再分段。
- 保存可追溯的摘要與原文位置，寫履歷時按職缺取用相關素材。
- 每次請求計算輸入預算，包含指令、來源、歷史內容與工具輸出，預留輸出空間；超限必須拆批。
- 維持全域履歷摘要，避免只因關鍵字檢索而遺漏必要工作經歷。
- 重要敘述回查來源，缺乏證據的內容不輸出為確定事實。
- 快取已確認摘要；失敗可續跑，不無限制重試。
- 能取得官方用量狀態時顯示；無法取得時不捏造剩餘百分比。token 估算不等於官方訂閱額度。
- 不超 context 只代表輸入受控，不代表內容絕不遺漏。

#### F06 職缺讀取

- 在使用者授權、明確觸發後讀取當前支援的職缺頁。
- 擷取公司、職稱、職責、必要條件、加分條件、地點、來源 URL 及擷取時間；不存在的欄位留空。
- 顯示可修改的職缺快照，後續客製履歷與面試皆關聯此快照。
- 擷取內容不足、登入失效或網站改版時停止並提示；保留手動匯入文字的備援路線。
- 不把「能開啟網站」等同於「已支援全部職缺與私訊頁」。

#### F07 職缺專用履歷與 PDF

- 對照職缺與經歷，整理匹配的能力、支持證據及待補充資訊。
- 修改自我介紹、經歷敘述、專案選擇及排序，保留真實公司、職稱與日期。
- 原文與修改稿可對照，支援逐段接受、退回及自行編輯；顯示簡短修改理由。
- 預覽後用固定履歷模板產出可選取文字的 PDF。
- 不要求完整還原 104 原 PDF 的視覺排版；模板外觀待設計。
- 匯出前檢查中文字型、缺字、文字截斷、分頁、連結及空白頁。
- 保存原始履歷與每個職缺的獨立版本，不覆寫原件。

#### F08 招募訊息與回覆草稿

- 對支援的平台，在使用者開啟並授權的對話中擷取已載入、使用者選定的訊息。
- 結合職缺、履歷及使用者回覆意圖產生草稿。
- 意圖不明時確認，例如接受邀約、詢問職務、婉拒；不擅自承諾面試時間、薪資或到職日。
- 草稿可編輯、一鍵複製，由使用者回原平台貼上送出。
- 不讀取無關對話，不把對方訊息內的指令當成本工具的控制命令。

#### F09 投遞與版本紀錄

- 使用者可標記主動投遞或對方邀約、日期與狀態。
- 保存職缺快照、履歷版本、匯出 PDF 與相關草稿。
- 匯出 PDF 不等於已投遞；以使用者確認記錄「實際投出版本」。
- 第二階段面試教練使用當次投遞快照，不直接套用後來修改的履歷。

### S6. 第二階段：面試教練

#### P2-01 文字陪練

輸入為職缺快照、實際投遞履歷、已確認專案素材與使用者補充。

- 模擬面試官，一次一題，依回答追問。
- 題型包含自我介紹、動機、專案細節、跨部門協作、職缺能力及經歷缺口。
- 提供具體回饋：是否回答問題、證據是否足夠、敘述是否清楚、與履歷是否一致。
- 協助重新組織回答並讓使用者重練，不編造經驗。
- 題目是模擬，不聲稱預知真正面試官的問題。

#### P2-02 語音陪練

- 同樣禁止另付 API 費用。
- 基準方案：輸出面試資料包，包含職缺、投遞履歷、專案摘要、陪練規則與待加強項目，由使用者帶入支援語音的官方 App 並手動開啟。
- 不承諾外掛自動注入官方 App 對話、啟動語音或讀回紀錄。
- 官方 App 的語音能力不代表 Claude Code、Codex 或第三方工具可直接取得相同功能。
- 一鍵交接、在編輯器內語音、離線語音辨識與朗讀可另做可行性驗證；若只能透過額外付費服務完成，延後或不做。
- 官方語音的模型、語言、配額及附件可用性，上線前重新驗證。

### S7. 建議架構（尚未定案）

1. **瀏覽器擴充功能**：TypeScript、Manifest V3、逐站 content script，處理授權與使用者觸發的頁面擷取。
2. **編輯器分頁**：React + TypeScript，提供資料匯入、校正、職缺管理、版本編輯、PDF 預覽及面試入口。可由擴充功能開啟。
3. **本機輔助程式**：建議 Node.js／TypeScript；負責本機資料、PDF 處理、文件索引、官方工具連接及工作狀態。以安裝精靈封裝，通訊方式在技術驗證後確定。
4. **供應商適配層**：三個服務各自處理資格檢查、登入、模型、執行、取消及配額錯誤；共同遵守訂閱限定規則。
5. **本機資料儲存**：建議 SQLite + 檔案，保存來源、確認狀態、摘要、快照與版本；不預設新增雲端帳號或資料同步。

純網頁能處理使用者選取的本機文件，但為連接本機官方 AI 工具，首版架構增加本機輔助程式。這是訂閱整合需求帶來的變更。

本機連接須限制來源並驗證請求，不讓任意網站呼叫本機程式或命令。模型與外部文件不可直接決定要執行的 shell 指令。

### S11. 討論補充規則〔補〕

與 S4–S10 衝突時以本節為準。括號內是對應的討論編號（見 `decisions.md`）。

#### R1 事實項與四態（C1）

- 經歷資料的最小單位是「事實項」：一個功能、交付物、個人角色、成果數字、使用人數、公開連結各是一項。專案摘要只是事實項的彙整，本身不帶確認狀態。
- 功能與交付物有完成狀態：計畫中／文件標示完成／使用者確認完成／未知（D4）。每個事實項都有依據：來源片段（SourceDocument 版本＋位置＋原文）及／或使用者確認（時間＋確認當下的文字）。沒有依據的一律視為未知。
- 三種使用者動作意義不同：
  - **接受修改稿**：只接受措辭，不確認其中任何事實項。
  - **確認事實項**：在事實項上逐項確認，記錄時間與當下文字。
  - **逐段確認**：使用者對某一段明確表示「本段內容屬實」，記錄時間與該段全文；用於使用者自己寫的或改過的段落。
- 生成稿的每一段都要列出所引用的事實項，以及該段把每一項寫成什麼完成程度（已完成／進行中／規劃中）。匯出前自動檢查：
  1. 引用的事實項存在。
  2. 寫成已完成的事實項必須是「使用者確認完成」（D14）；計畫中、未知、待複核、來源矛盾一律不得寫成已完成。
  3. 文字中的數字（百分比、人數、金額、年份）出現在引用的事實項、個人資料欄位或使用者確認過的文字中。
- 檢查 2 不通過的段落，只能改寫、刪除，或到事實項上確認，不能用逐段確認繞過；檢查 1、3 不通過或沒有任何引用的段落，可以改寫、刪除或逐段確認。處理完之前不能匯出。
- 〔第 2 輪補〕生成段落的引用在編輯時保留：使用者可以增加引用，不能只移除引用；要去掉引用只能刪除整段。所以仍帶引用的段落一律受檢查 2 約束；能靠逐段確認匯出的無引用段落，只有使用者自己新寫的段落，以及生成時就沒有任何引用的段落。
- 措辭與宣稱的完成程度是否相符無法自動判定，由使用者在 F07 的逐段對照中把關。
- 公司、職稱、任職日期由個人資料欄位帶入模板，不交給模型生成。

#### R2 來源變更與確認失效（C2）

- 事實項的來源片段綁定 SourceDocument 的內容版本與片段原文。
- 〔第 2 輪改〕增量更新時，看引用片段**所在的區塊**（以標題或空行分隔的段落）：區塊完全沒變 → 保留原狀態；區塊有任何變更或片段消失 → 事實項改為「待複核」，處理前不得用於新的生成。已經使用者確認的也一樣，因為新內容可能和確認相矛盾。字串仍在不代表依據仍有效（例如同一段加上「先前記載有誤」）。
- 來源檔被刪除或撤銷授權：只靠該來源的事實項不得再用於新的生成；已經使用者確認的可以保留，依據只剩使用者確認，畫面標示「來源已移除」。
- 〔第 2 輪改〕文件其他部分有變更時，重新分析該文件。分析發現來源互相矛盾（兩份文件之間，或同一文件內的更正、撤回，例如一處寫完成、另一處寫計畫中或已撤下），事實項標示「來源矛盾」，按未知處理，直到使用者確認。
- 已匯出的版本保存當時引用片段的副本（R3），不受來源後續變更影響。

#### R3 匯出版本與投遞凍結（C3）

- 每次匯出 PDF 都產生一個不可變的「匯出版本」：履歷全文、PDF 檔與雜湊、引用的事實項與片段原文副本、當時職缺快照的副本。之後的任何編輯都產生新版本，不改舊版。
- 使用者標記「實際投出」時，只能指向某一個匯出版本。〔第 2 輪補〕投遞流程不能附自訂 PDF、使用者改填站內履歷時，實際投出版本怎麼記，見 D20；在 S10 驗證並定案前，不得把內容來源的那份 PDF 記成實際投出版本。
- 第二階段面試教練的輸入只從該匯出版本讀取。
- 〔第 2 輪改〕刪除素材時，各匯出版本（已投遞與未投遞）保存的副本：未投遞的整份刪除，已投遞的保留並明示（D19）。

#### R4 檔案授權集合（C4）

- 使用者選取資料夾，只授權本工具「列出其中的檔名、大小、類型」（F03 的先列舉）；讀取內容只限使用者在預覽中確認過的檔案，這些檔案構成「授權集合」。
- 本機輔助程式的讀檔介面只接受授權集合內的檔案；每次讀取記錄路徑、時間與內容雜湊，供驗收比對。
- 增量更新時重新列舉資料夾：新出現的候選文件標示「待確認」，確認前不讀內容；授權集合內已變更的檔案可以重讀（再套用 R2）；使用者取消勾選或移除資料夾後立即停止讀取。
- 不跟隨指向所選資料夾以外的符號連結或捷徑。讀取前確認實際路徑仍在所選資料夾內、仍是一般檔案、仍符合文件類型篩選，不符就跳過並提示。
- F03 的「自訂檔名」仍限文字文件類型，不能藉此加入原始碼（D5）。

#### R5 供應商呼叫隔離（C5）

- 適配層呼叫官方 CLI 時必須同時做到：
  1. 模型不能執行 shell、不能自行讀寫檔案、不能使用網頁擷取或搜尋工具、不能呼叫 MCP 或外掛。
  2. 不載入使用者自己的全域指令檔、hooks、MCP 設定與外掛。
  3. 工作目錄是空的暫存資料夾，不是專案資料夾；專案的 CLAUDE.md、AGENTS.md 只以引用資料的形式放進提示。
  4. 所有輸入由本機輔助程式組好放進提示。
- 只靠提示詞寫「不要執行」，或只用 CLI 的唯讀沙箱，都不算達成：唯讀沙箱仍可讀檔（codex 0.159.3 `--help`：`-s` 是「執行模型產生的 shell 指令時」的沙箱政策）。
- 每家以 S9-13 證明；證明不了的那家標示「尚未支援」（S8 最後一條），其他已通過的照常可用。

#### R6 訂閱路線確認（C6）

- 每次執行前（包括排隊中的工作開始時、暫停後續跑時）都重新確認，不沿用安裝精靈當時的結果：
  1. 官方工具自己回報目前是訂閱登入，不是 API key。
  2. 子程序的環境變數移除已知的 API key 與雲端計費設定；偵測到 CLI 設定會改走 API key 或其他計費供應商時，阻擋。
  3. 不使用會改走 API key 的執行模式。例：claude 2.1.296 `--help` 寫明 `--bare` 只讀 `ANTHROPIC_API_KEY` 或 apiKeyHelper、不讀 OAuth 登入，所以禁用。
  4. 〔D12〕不檢查使用者自行開啟的額外用量／點數；工具回報額度用完就依 R9 停止。
- 每次確認的結果與依據寫進該次執行紀錄，這份紀錄就是 S9-2 的證據。任何一項不成立就不執行。

#### R7 本機橋接介面的能力邊界（C7）

- 擴充功能、編輯器分頁與本機輔助程式之間只提供固定的操作清單，例如：送入職缺頁擷取內容、送入使用者選定的訊息、要求產生草稿、開啟編輯器。
- 頁面、文件、訊息與模型輸出的內容一律只是資料欄位，不能變成檔案路徑、CLI 參數、模型設定或指令。
- 檔案只能經由使用者在系統選取器加上預覽確認的流程進入授權集合（R4）；介面不接受外部傳入的任意路徑。
- 介面沒有送出訊息、投遞或在求職網站上填寫的操作（D7）。
- 來源驗證只回答「是誰在呼叫」，不代表請求的內容可信。Q3 不論選哪種通訊方式都要符合本條。

#### R8 輸入預算的計量邊界（C8）

- 預算 ＝ 該模型的上下文上限 － 輸出預留 － 官方工具自身開銷預留（系統提示等，無法精確觀測，取保守值）。上下文上限以官方文件或工具回報為準，查不到就用保守的預設值。
- 計量對象是本機輔助程式組裝的全部輸入：指令、來源片段、全域履歷摘要、歷史內容。依 R5 不開工具，所以沒有工具輸出。
- 估算超過預算就拆批，不得送出；每一批記錄估算值、所用上限與來源位置。估算不等於官方額度（F05）。

#### R9 中斷與續跑（C9）

- 長工作拆成單元（一份文件的一段、一個專案的分析、一份履歷的生成）。單元完成並通過檢查才寫入；未完成單元的部分輸出一律丟棄。
- 額度耗盡或使用者取消：停止目前單元並丟棄其輸出，已完成單元保留，工作標記「已暫停」並顯示原因。取消後才回來的結果直接丟棄。
- 〔第 2 輪改〕工作狀態存在本機資料庫，輔助程式重開後進度仍在；續跑時從第一個未完成單元開始，續跑前重做 R6。續跑一律由使用者主動觸發（D21），不自動續跑。
- 暫停時，使用者可以改用另一個已授權的服務繼續（`Spec.md` §2 第 3 條）。切換只發生在單元之間，每個單元記錄所用的服務與模型；F01「每項任務使用一個選定模型」指的是每個單元。
- 額度錯誤不自動重試；網路等暫時性錯誤自動重試有上限（預設 2 次，間隔逐次拉長）。

#### R10 擷取完整性與 PDF 解析確認（C10）

- 每個平台適配器定義必要欄位；職缺頁至少要有公司、職稱、職缺描述本文，訊息頁至少要有使用者選定訊息的全文。必要欄位缺任何一個就視為擷取失敗：停止並提示改用手動貼上，不建立標成「自動擷取」的快照或訊息。
- 選用欄位（加分條件、地點等）：找不到頁面結構時記為「未擷取到」，結構存在但內容空白時記為「頁面未提供」；兩種都在快照上標示，使用者確認快照後才能用於生成。
- 職缺快照與訊息都記錄擷取方式（自動／手動貼上）及使用者是否改過；畫面與紀錄不得把手動匯入標成自動（S9-8）。
- 逐站驗證時保存代表性樣本與預期欄位作為回歸測試（訊息頁樣本須去識別化），網站改版造成必要欄位缺失時要測得出來。
- PDF 匯入的解析結果經使用者確認後才能用於生成；偵測到大量亂碼或讀取順序異常時直接提示，不預設為成功。
