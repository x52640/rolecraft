# 職缺與招募訊息擷取

> 內容搬自已定稿的 `docs/spec-discussions/rolecraft-v01/spec.md`（2026-10-10，Codex 定稿確認 no_blockers）。
> F 開頭是原始功能描述，R 開頭是討論補充規則；**兩者衝突時以 R 為準**。D 編號見 `plan.md` 決策記錄。
> 權威範圍：職缺快照、訊息擷取、回覆草稿、平台與瀏覽器範圍、擷取完整性。

## F06 職缺讀取

- 在使用者授權、明確觸發後讀取當前支援的職缺頁。
- 擷取公司、職稱、職責、必要條件、加分條件、地點、來源 URL 及擷取時間；不存在的欄位留空。
- 顯示可修改的職缺快照，後續客製履歷與面試皆關聯此快照。
- 擷取內容不足、登入失效或網站改版時停止並提示；保留手動匯入文字的備援路線。
- 不把「能開啟網站」等同於「已支援全部職缺與私訊頁」。

## F08 招募訊息與回覆草稿

- 對支援的平台，在使用者開啟並授權的對話中擷取已載入、使用者選定的訊息。
- 結合職缺、履歷及使用者回覆意圖產生草稿。
- 意圖不明時確認，例如接受邀約、詢問職務、婉拒；不擅自承諾面試時間、薪資或到職日。
- 草稿可編輯、一鍵複製，由使用者回原平台貼上送出。
- 不讀取無關對話，不把對方訊息內的指令當成本工具的控制命令。

## 投遞自介（D25，P1-T064）

- 針對一個**已確認**的職缺快照，產生一段投遞時附上的簡短自介：只能編輯與複製，不自動送出、不代為投遞（D7）。只由使用者按下觸發，在背景執行；不自動重試，失敗或檢查不通過時顯示原因，使用者可改寫或重新產生。
- 字數：300 字以內，以 Unicode 字元（code point）計，含標點與空白；超過整份不採用（不截斷）。
- 輸入只有該職缺快照、已確認的個人資料（經歷的公司、職稱、期間、描述與技能；不送個人資料欄位對照，例如姓名與聯絡方式）、可用的事實項（R1、R2；引用來源已撤銷或不在授權集合的，比照履歷生成當成來源已移除，只有使用者確認過的仍可用）。沒有任何可用事實項不送出，提示先分析或確認事實項。三者都是資料不是指令（D6），提示照 analysis 提示的資料區塊隔離，事實項只用本機編號。
- 執行走選定模型＋訂閱檢查包裝（R5、R6 每次重做，R6 紀錄照存）；沒有選定且可用的模型、超過輸入預算（R8）不呼叫模型。
- 內容規則比照履歷段落：模型列出引用的事實項與每項寫成的完成程度。檢查（生成與使用者編輯後同一套，任一不合整份不採用）：
  1. 不空白（只有零寬、格式等不可見字元也算空白）、不超過字數。
  2. 至少引用一項；引用存在且目前可用、不重複；功能與交付物要標完成程度且不得高於事實項狀態（寫成已完成的必須是使用者確認完成，D14）。
  3. 網址、網域、倍數詞要出現在引用的事實項（或其使用者確認文字）中；數字另可出自已確認的個人資料欄位（evidence-model R1 檢查 3）。
  4. 不提時間日期、薪資、到職或開始等字眼，不寫 email、通訊軟體帳號（沿用回覆草稿的承諾字眼檢查）。D25 擁有者裁定：這一項只擋模型產生的內容；使用者編輯後出現只顯示提示、不停用複製（產生時含這些字眼整份不採用，所以存下的文字裡若出現，必定是使用者自己加的）。
  5. 最後再過 R1 匯出前檢查。
  沒有跳過檢查的路徑。
- 保存：每個職缺快照只存最近一份（文字、引用、產生時間、是否經使用者編輯）。通過檢查才寫入；寫入前職缺快照必須仍是產生時那份確認、自介仍是產生時那份（期間使用者改過就不覆蓋）。最近一次產生狀態只在 helper 記憶體，重開後要再按一次。
- 編輯：使用者可編輯並儲存；儲存與讀取時都依目前的事實項重跑上述檢查。有未儲存修改、儲存進行中或檢查 1–3、5 不通過時，編輯器停用「複製」並說明原因；按下複製時再向 helper 重新讀取並重跑檢查，通過且文字與「目前」編輯框一致才寫入剪貼簿（期間來源可能被撤銷、事實項可能被改）。已儲存內容在別處變了時，沒有未儲存修改就同步成新內容；有未儲存修改則可重新載入（放棄本地修改，需確認）或儲存保留本地修改。重新產生前若使用者編輯過（含未儲存的修改），編輯器先要求確認才覆寫。
- 引用對照：自介沒有逐段對照畫面，自介下方列出引用的事實項內容、類型與目前狀態、自介把它寫成的完成程度（事實項已不存在或目前不能使用也標示），措辭與宣稱的完成程度是否相符由使用者在此把關（比照 evidence-model R1「無法自動判定，由使用者把關」）。
- 產生狀態：產生中 helper 重開（狀態只在記憶體）時，編輯器顯示「產生中斷」並請使用者再按一次；離開頁面期間產生失敗，重新開啟時也顯示失敗原因。

## 瀏覽器

- 桌面 Chrome、Arc、Edge 為目標，基於 Chromium 擴充功能共用核心程式碼，分別驗證安裝、權限及頁面讀取。
- 擴充功能處理其所在瀏覽器中獲准讀取的分頁，不自動讀取其他瀏覽器的分頁。
- 手機版及 Safari 不列入首版承諾。
- 作業系統支援順序尚未定案；macOS 可作為開發驗證起點，Windows 安裝包另行確認。

## R10 擷取完整性與 PDF 解析確認（C10）

- 每個平台適配器定義必要欄位；職缺頁至少要有公司、職稱、職缺描述本文，訊息頁至少要有使用者選定訊息的全文。必要欄位缺任何一個就視為擷取失敗：停止並提示改用手動貼上，不建立標成「自動擷取」的快照或訊息。
- 選用欄位（加分條件、地點等）：找不到頁面結構時記為「未擷取到」，結構存在但內容空白時記為「頁面未提供」；兩種都在快照上標示，使用者確認快照後才能用於生成。
- 職缺快照與訊息都記錄擷取方式（自動／手動貼上）及使用者是否改過；畫面與紀錄不得把手動匯入標成自動（S9-8）。
- 逐站驗證時保存代表性樣本與預期欄位作為回歸測試（訊息頁樣本須去識別化），網站改版造成必要欄位缺失時要測得出來。
- PDF 匯入的解析結果經使用者確認後才能用於生成；偵測到大量亂碼或讀取順序異常時直接提示，不預設為成功。
