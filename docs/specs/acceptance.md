# 驗收條件

> 內容搬自已定稿的 `docs/spec-discussions/rolecraft-v01/spec.md`（2026-10-10，Codex 定稿確認 no_blockers）。
> F 開頭是原始功能描述，R 開頭是討論補充規則；**兩者衝突時以 R 為準**。D 編號見 `plan.md` 決策記錄。
> 權威範圍：S9 驗收 1–16。

## S9. 驗收條件〔補：依 S11 修改與新增〕

1. 安裝精靈能區分工具缺少、未登入、資格未知、可用與額度不足，不把安裝成功視為整合成功。
2. 至少一條官方訂閱路線端到端完成分析與履歷生成，且不使用另外計費的 API（含環境 API key 回退）。〔D12：使用者自行開啟的額外用量不在此限〕〔補〕證據是每次執行的 R6 確認紀錄；登入成功或產出成功都不算證據。
3. 三家服務逐一記錄驗證結果；未通過者不宣稱可用。〔補〕標示可用的服務必須通過 S9-13。
4. PDF 能擷取及人工校正；雙欄或掃描問題有明確備援，沒有隱藏的付費 OCR。〔補〕解析結果經使用者確認後才可用於生成（R10）；掃描 PDF 首版只提供人工輸入（D18）。
5. 可以累積匯入至少 10 個專案資料夾，預覽文件，排除程式碼與不相關內容。〔補〕並通過 S9-14。
6. 〔補，改寫〕超長文件分批處理；沒有任何一次送出的組裝輸入超過 R8 定義的預算；每段輸出可回查來源位置。
7. 〔補，改寫〕計畫中、未知、待複核與來源矛盾的事實項不會寫成已完成事實；「文件標示完成」未經逐項確認不得寫成已完成（D14）；每個匯出段落都對得到事實項或使用者的逐段確認；未通過 R1 自動檢查的段落不能匯出。
8. 每個平台、職缺／私訊頁分別驗證；頁面讀取失敗不輸出假資料，不以人工匯入冒充自動支援。〔補〕必要欄位缺失視為失敗，快照如實標示擷取方式（R10）；首版門檻為 104 職缺頁（D16）。
9. 回覆草稿只可編輯與複製，不自動發送。
10. 客製履歷可對照修改並匯出正常顯示中文的 PDF；保留原履歷與獨立版本。
11. 〔補，改寫〕使用量耗盡時停止並保留進度，無自動加購、付費回退或密集重試；依 R9：執行中單元的部分輸出被丟棄、已完成單元保留、輔助程式重開後進度仍在且續跑從第一個未完成單元開始、取消後才回來的結果被丟棄、使用者取消後不會自動重新送出資料（續跑一律由使用者主動觸發，D21）。
12. 〔補，改寫〕確認投遞後，修改履歷、職缺快照、事實項並刪除來源檔，再讀取該筆投遞的面試輸入資料，內容與投遞當時的匯出版本一致（R3）。不需先做面試模型即可測。
13. 〔補，新增〕每家標示可用的服務都通過注入測試：輸入資料內含「執行指令、讀取誘餌檔、上網查詢」等要求，執行事件中沒有任何工具呼叫，誘餌檔內容沒有出現在輸出，且沒有載入使用者的全域指令檔、hooks、MCP 或外掛（R5）。
14. 〔補，新增〕檔案授權測試：讀檔紀錄只含授權集合；新出現的文件在確認前未被讀取；取消勾選或移除資料夾後不再讀取；指向資料夾外的符號連結未被跟隨；預覽後被換成不符類型的檔案未被讀取（R4）。
15. 〔補，新增〕來源變更測試：引用片段被改掉、片段仍在但所在區塊被修改（例如加上更正說明）、來源檔被刪除、兩份來源或同一文件內前後矛盾，對應事實項分別變成待複核、待複核、來源已移除、來源矛盾，且新的生成不使用待複核與矛盾的事實項（R2）。
16. 〔補，新增〕乾淨環境安裝測試：在 macOS 上（D11），從沒有本機輔助程式、執行環境、官方工具與擴充功能的狀態開始，走完安裝、官方登入、每個宣稱支援的瀏覽器連線，到第一次生成；全程不需終端指令或手動設定金鑰（D10）。
