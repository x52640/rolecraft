# AI 供應商連接

> 內容搬自已定稿的 `docs/spec-discussions/rolecraft-v01/spec.md`（2026-10-10，Codex 定稿確認 no_blockers）。
> F 開頭是原始功能描述，R 開頭是討論補充規則；**兩者衝突時以 R 為準**。D 編號見 `plan.md` 決策記錄。
> 權威範圍：安裝精靈、登入／計費檢查、CLI 隔離、各家狀態。

## F01 安裝精靈及訂閱連接

目標服務為 Claude、ChatGPT／Codex、Google Antigravity。

流程：檢查本機輔助程式與官方工具 → 顯示已安裝／未安裝、已登入／未登入 → 引導必要安裝與官方授權 → 確認可用資格與計費方式 → 列出可選服務及模型 → 由使用者選定。

- 「已安裝」或「已登入」不等於有付費訂閱，也不等於本次操作可以免額外付費。
- 不能承諾自動發現所有訂閱；官方工具未提供方案資訊時，顯示未知並引導確認。
- 模型選單依服務實際提供及帳號資格產生，不假設所有模型可用。
- 首版每項任務使用一個選定模型，允許使用者切換服務；混合模型架構技術上可行，並非永久限制。
- 〔P1-T058〕有資料區時，選定的模型（存模型本身，不存每次啟動重新配發的候選 ID）、連接狀態、每次 R6 確認紀錄、通過自動重新驗證的 Claude CLI 版本（D22）存進資料區。重啟後選定模型保留，但服務狀態一律需重新檢查，不沿用舊的可用（重新檢查由 P1-T070 自動做）。選定要先寫進資料區才生效；短驗證的 R6 紀錄寫不進去，該次驗證視同失敗。沒有資料區時全在記憶體。
- 〔P1-T062，D24 修改 D22 的失敗處理〕Claude CLI 版本紀錄每個版本以最後一筆為準，分三種：verified（接受）、failed（停用）、incomplete（未完成）。
  - 呼叫模型前先存 incomplete 暫定紀錄；之後沒有結果就是中途被打斷（程序結束、斷電），不算失敗：狀態為「需要重新驗證」，下次**使用者發起**需要 Claude 的工作（重新檢查、選定模型、生成／分析）時自動重跑（仍先存暫定紀錄）。helper 啟動、狀態查詢不呼叫模型。P1-T058 舊格式的暫定紀錄（outcome=failed、reason=`重新驗證未完成`、沒有案例）讀成 incomplete。
  - 失敗只綁版本：只有「目前偵測到的 CLI 版本」最後一筆是 failed 才停用，不自動重試；CLI 換成沒有失敗紀錄的版本照 D22 自動重新驗證，換回失敗的版本仍停用。
  - 重新啟用：目前版本 failed 或 incomplete 時，使用者在設定頁按「重新啟用」，helper 在背景對目前版本重跑注入測試（S9-13，模型呼叫上限同 D22），通過才接受；與一般執行互斥、R6 不通過不呼叫模型、先存暫定紀錄等保護不變；不通過就新增一筆 failed。其他情況（已驗證、沒有紀錄）不跑，回「不需要」。沒有「不測就放行」的路徑。
  - 結果寫不進資料區：真的失敗時再試一次寫入精簡失敗紀錄（只留未通過的案例）；兩次都寫不進去，這次執行仍停用該版本，但資料區最後一筆是暫定紀錄，重啟後退化為「未完成」（下次使用者發起工作會再重跑）。通過但寫不進去：只在記憶體停用，不補寫失敗。
  - 使用者發起的重新檢查先讀目前 CLI 版本，再做連線檢查（不會因為上一個版本停用而讀不到新版本）。狀態查詢的停用／未完成原因從閘門即時算（除 P1-T070 的第一次自動檢查外不啟動任何程式）；目前版本停用或未完成時狀態為「尚未支援」，先前因版本問題不可用而問題已不在時顯示「資格未知」（需重新檢查）。
- 〔P1-T070〕helper 重開後不必手動按「重新檢查」：
  - 自動檢查（不呼叫模型）：本程序還沒檢查過 Claude 時，設定頁讀狀態、選定模型前先自動做一次，只讀 CLI 版本與登入狀態（R5 版本閘門、R6 登入方式與方案），並行請求共用同一次。沒有紀錄、未完成或停用的版本在這裡不重新驗證，狀態為「尚未支援」。檢查本身出錯不算檢查過，下次再試；檢查過之後狀態查詢不再觸發檢查。
  - 使用者發起需要 Claude 的工作（生成、分析、自介、回覆草稿）時：沒選定模型就不檢查，直接回「尚未選定模型」。已選定且目前狀態不是可用（還沒檢查、只做過自動檢查、或上次一般檢查沒通過）就做一次一般檢查，D22／D24 照常（沒有紀錄或未完成的版本自動重新驗證；停用的版本不重試，只重讀版本與登入）；額度用完不重新檢查（訊息指示額度恢復後到設定頁按「重新檢查」）。通過才執行。手動「重新檢查」與這裡的一般檢查共用進行中的同一次，不另開。
  - 這次請求最多等一般檢查 20 秒（橋接逾時 30 秒）；還沒結束就回「正在檢查，請稍後再試」，檢查在背景繼續，下次發起接著等同一次，期間讀狀態不另外開檢查。
  - 先開始的檢查比後開始的晚結束：結果丟棄；例外是它通過、而較新的那次是純版本問題（找得到 CLI、確認不了版本，且登入、方案、訂閱路線都沒有確定失敗；例如重新驗證進行中被擋），這時採用通過的結果。較新的那次只要有確定的登入或訂閱路線失敗（例如登出、改走 API key、方案不符），一律保留較新的結果。
  - 不通過不執行，失敗訊息帶具體原因（未裝 CLI、未登入、無法確認方案、改走 API key、版本停用或待驗證、額度用完、未選模型）；原因只由狀態欄位組成，不含路徑（R7）。
  - helper 啟動、背景輪詢不檢查；每次執行前的 R6 不變。
- 〔改，D12〕使用者自己開啟的額外用量功能不擋；只擋非使用者主動選擇的付費路線（API key 回退、自動加購）。
- 不宣稱 Claude、Codex、Antigravity 的登入、額度查詢和安裝方式完全一致，須分別適配與驗證。
- 本機程式啟動不代表模型在本機推論；資料仍可能送至所選供應商，介面需清楚標示。

## R5 供應商呼叫隔離（C5）

- 適配層呼叫官方 CLI 時必須同時做到：
  1. 模型不能執行 shell、不能自行讀寫檔案、不能使用網頁擷取或搜尋工具、不能呼叫 MCP 或外掛。
  2. 不載入使用者自己的全域指令檔、hooks、MCP 設定與外掛。
  3. 工作目錄是空的暫存資料夾，不是專案資料夾；專案的 CLAUDE.md、AGENTS.md 只以引用資料的形式放進提示。
  4. 所有輸入由本機輔助程式組好放進提示。
- 只靠提示詞寫「不要執行」，或只用 CLI 的唯讀沙箱，都不算達成：唯讀沙箱仍可讀檔（codex 0.159.3 `--help`：`-s` 是「執行模型產生的 shell 指令時」的沙箱政策）。
- 每家以 S9-13 證明；證明不了的那家標示「尚未支援」（S8 最後一條），其他已通過的照常可用。

## R6 訂閱路線確認（C6）

- 每次執行前（包括排隊中的工作開始時、暫停後續跑時）都重新確認，不沿用安裝精靈當時的結果：
  1. 官方工具自己回報目前是訂閱登入，不是 API key。
  2. 子程序的環境變數移除已知的 API key 與雲端計費設定；偵測到 CLI 設定會改走 API key 或其他計費供應商時，阻擋。
  3. 不使用會改走 API key 的執行模式。例：claude 2.1.296 `--help` 寫明 `--bare` 只讀 `ANTHROPIC_API_KEY` 或 apiKeyHelper、不讀 OAuth 登入，所以禁用。
  4. 〔D12〕不檢查使用者自行開啟的額外用量／點數；工具回報額度用完就依 R9 停止。
- 每次確認的結果與依據寫進該次執行紀錄，這份紀錄就是 S9-2 的證據。任何一項不成立就不執行。

## S8. 訂閱整合的已查證資訊與限制

以下為 2026-10-10 討論時查閱的官方資料，不代表本產品整合已通過實測：

- Claude 官方 2026-10-07 更新指出，Agent SDK、claude -p 與第三方應用仍可使用訂閱限制內的用量。採用何種登入及計費路線仍須驗證，不能讓環境中的 API key 導致額外收費。
- OpenAI 提供 ChatGPT 訂閱登入及授權應用使用方案額度的文件。應用註冊、資格、模型權限及目前預覽限制須按官方流程確認，不因使用者有 ChatGPT 就保證所有第三方路線都可用。
- Google 官方開發者論壇說明，個人本機程式可呼叫未修改的官方 Antigravity CLI，使用本人訂閱登入；不可擷取憑證轉接私人端點，不可共用成多人服務。
- 三家皆不得承諾無限額度，也不得把某個服務的訂閱用量自動轉給另一家。
- 若某家的官方支援、資格或零額外收費條件不成立，顯示「尚未支援／無法確認」，其餘已驗證服務仍可使用。
