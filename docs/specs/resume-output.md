# 客製履歷、匯出版本與投遞

> 內容搬自已定稿的 `docs/spec-discussions/rolecraft-v01/spec.md`（2026-10-10，Codex 定稿確認 no_blockers）。
> F 開頭是原始功能描述，R 開頭是討論補充規則；**兩者衝突時以 R 為準**。D 編號見 `plan.md` 決策記錄。
> 權威範圍：逐段修改、PDF 匯出、不可變匯出版本、投遞紀錄。

## F07 職缺專用履歷與 PDF

- 對照職缺與經歷，整理匹配的能力、支持證據及待補充資訊。
- 修改自我介紹、經歷敘述、專案選擇及排序，保留真實公司、職稱與日期。
- 原文與修改稿可對照，支援逐段接受、退回及自行編輯；顯示簡短修改理由。
- 預覽後用固定履歷模板產出可選取文字的 PDF。
- 不要求完整還原 104 原 PDF 的視覺排版；模板外觀待設計。
- 匯出前檢查中文字型、缺字、文字截斷、分頁、連結及空白頁。
- 保存原始履歷與每個職缺的獨立版本，不覆寫原件。

## F09 投遞與版本紀錄

- 使用者可標記主動投遞或對方邀約、日期與狀態。
- 保存職缺快照、履歷版本、匯出 PDF 與相關草稿。
- 匯出 PDF 不等於已投遞；以使用者確認記錄「實際投出版本」。
- 第二階段面試教練使用當次投遞快照，不直接套用後來修改的履歷。

## R3 匯出版本與投遞凍結（C3）

- 每次匯出 PDF 都產生一個不可變的「匯出版本」：履歷全文、PDF 檔與雜湊、引用的事實項與片段原文副本、當時職缺快照的副本。之後的任何編輯都產生新版本，不改舊版。
- 使用者標記「實際投出」時，只能指向某一個匯出版本。〔第 2 輪補〕投遞流程不能附自訂 PDF、使用者改填站內履歷時，實際投出版本怎麼記，見 D20；在 S10 驗證並定案前，不得把內容來源的那份 PDF 記成實際投出版本。
- 第二階段面試教練的輸入只從該匯出版本讀取。
- 〔第 2 輪改〕刪除素材時，各匯出版本（已投遞與未投遞）保存的副本：未投遞的整份刪除，已投遞的保留並明示（D19）。
