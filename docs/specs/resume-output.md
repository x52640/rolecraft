## F07 職缺專用履歷與 PDF

- 對照職缺與經歷，整理匹配的能力、支持證據及待補充資訊。
- 修改自我介紹、經歷敘述、專案選擇及排序，保留真實公司、職稱與日期。
- 原文與修改稿可對照，支援逐段接受、退回及自行編輯；顯示簡短修改理由。
- 預覽後用固定履歷模板產出可選取文字的 PDF。
- 不要求完整還原 104 原 PDF 的視覺排版；模板外觀待設計。
- 匯出前檢查中文字型、缺字、文字截斷、分頁、連結及空白頁。
- 保存原始履歷與每個職缺的獨立版本，不覆寫原件。

## F09 投遞與版本紀錄

- 使用者可標記主動投遞或對方邀約、日期與狀態。
- 保存職缺快照、履歷版本、匯出 PDF 與相關草稿。
- 匯出 PDF 不等於已投遞；以使用者確認記錄「實際投出版本」。
- 第二階段面試教練使用當次投遞快照，不直接套用後來修改的履歷。

## R3 匯出版本與投遞凍結（C3）

- 每次匯出 PDF 都產生一個不可變的「匯出版本」：履歷全文、PDF 檔與雜湊、引用的事實項與片段原文副本、當時職缺快照的副本。之後的任何編輯都產生新版本，不改舊版。
- 使用者標記「實際投出」時，只能指向某一個匯出版本。〔第 2 輪補〕投遞流程不能附自訂 PDF、使用者改填站內履歷時，實際投出版本怎麼記，見 D20；在 S10 驗證並定案前，不得把內容來源的那份 PDF 記成實際投出版本。
- 第二階段面試教練的輸入只從該匯出版本讀取。
- 〔第 2 輪改〕刪除素材時，各匯出版本（已投遞與未投遞）保存的副本：未投遞的整份刪除，已投遞的保留並明示（D19）。

## Profile 修改後的過期提示（D30 (a)）

- **記錄**：helper 存下履歷版本（`resume.generate` 的結果）時，相加選填記下產生時的 Profile 版本號（`profileVersion`）＝這次生成**最後一次送出模型時實際讀到**的那份 Profile 的版本號（runner 每次送出前會重讀，取最後送出那次；不得在存檔時另外重讀）。Profile 沒有版本號（舊資料）記 0。之後的段落編輯、接受、確認都不改這個值；只有重新產生的新版本記新值。
- **比對**：舊的履歷版本沒有 `profileVersion` 視為 0（版本號從 P1-T090 起才會增加，所以那之後 Profile 有任何修改或重新匯入確認，舊版本都會被判為過期）。履歷頁開啟某個版本時讀 `profile.get`，目前版本號（沒有視為 0）與該版本的 `profileVersion` 不同就在版本上方顯示固定提示「個人資料在此版本產生後改過」，並附一句「需要的話重新產生」。改了又改回原值也算改過（只比版本號，不比內容）。
- **只提示**：不擋匯出、不擋複製、不改段落與 `decision`，不進 `resume.check_export` 的 blockers；匯出前檢查照現行規則（對不到經歷照樣擋，resume-import「個人資料編輯（D30）」）。已匯出版本不可變，不顯示這個提示。
- `profile.get` 失敗、沒有 Profile、多份 Profile 時不顯示提示（無從比對），也不因此擋其他操作。履歷頁重新整理或切換版本時重新比對；不自動輪詢。
- **驗收**：產生版本後經 `profile.update` 或 `import.confirm` 改過 Profile，履歷頁顯示提示、仍可匯出；未改過不顯示；舊版本（沒有記錄）在 Profile 版本號 0 時不顯示、大於 0 時顯示；生成途中 Profile 被改，記下的是最後一次送出時讀到的版本號；`profile.get` 失敗時不顯示、不擋。

## 照片（D28）

- **存放**：資料區只存一張「目前的照片」，獨立於 Profile（Profile schema 不變、不進 `ProfileInput`；匯入、AI 重整、確認都不碰照片）。存在資料庫，不放進檔案儲存區（避免被孤兒清掃刪掉）。
- **加入**：`photo.pick`：helper 開系統選取器（只限 JPEG／PNG、10 MB 以下），解碼後重新編碼成 JPEG、最長邊縮到 1,200 px，並去掉所有中繼資料（EXIF，含 GPS 位置與拍攝裝置；N1）；解不開就拒絕。使用者在選取器選定、處理成功即生效，不等匯入確認。請求沒有路徑；回應只有照片資訊（格式、尺寸、雜湊）與縮圖。repo 目前沒有影像處理相依，做法（例如用匯出已在用的 Chrome 重繪）由實作 Task 決定，但要以「存下的結果沒有中繼資料」驗證。
- `photo.pick` 列入選取器操作（contracts `BRIDGE_PICKER_OPERATIONS`，用選取器的長逾時）；解碼與重新編碼必須在選取器的處理餘裕內完成，超過就放棄、不寫入。客戶端逾時不會取消 helper 的工作，所以 `photo.*` 失敗或逾時後，編輯器一律重新讀 `photo.get`，以實際狀態顯示（W19）。
- **查詢與刪除**：`photo.get`（目前照片資訊＋縮圖，回應低於 1 MiB）、`photo.remove`。
- **匯出**：匯出文件（pdf-export `ResumeDocument`）相加選填照片（data URI），模板在頁首放照片；沒有照片時版面照常。匯出版本相加記錄照片 ID 與雜湊（R3）。照片不送模型、不出現在任何提示。
- **刪除與更換**：照片印進匯出 PDF 後就是「素材」（匯出版本保存了它的副本），刪除照片套 D19：含這張照片、未投遞的匯出版本整份刪除，已投遞的保留並明示；確認前畫面先說明。素材身分是照片 ID：每次加入（含更換）都由 helper 配發新的照片 ID，刪除時以照片 ID 記入已刪素材；不用雜湊當身分（刪掉後再選同一張照片，新的匯出不能因此被擋；W12）。更換視同刪除舊照片：更換＝刪除舊照片＋加入新照片，在同一個交易完成；已有照片時，畫面先說明、使用者確認後才開選取器，取消選取不變動。
- **驗收**：選取、更換、刪除；存下的照片沒有 EXIF 等中繼資料；刪除與更換照 D19 處理含照的匯出版本；刪掉後再選同一張照片，新的匯出不被擋；選取超過一般逾時仍能完成，失敗或逾時後畫面顯示的是 `photo.get` 讀回的實際狀態；匯出含照片／不含照片兩種版面，含照版要目視確認照片有印出、沒有遮住文字（W17：`inspect` 不檢查圖片）；照片不出現在任何提示。

## 內容回填到求職網站（D28）

- **第一階段（現行）**：履歷頁與自介頁提供「複製」按鈕，使用者自己貼到網站，不需要任何網站權限。依內容來源分開把關（W13）：
  - **已確認的個人資料**（個人資料各欄、每段經歷的公司／職稱／日期／描述、技能）：唯讀操作 `profile.get`；按下時向 helper 重新讀取已確認的 Profile，讀回的值與畫面一致才複製；不一致就把畫面更新成讀回的內容、請使用者確認後再按一次（Q12＝A，比照自介）。
  - **客製履歷段落**：以 `resume.check_export` 的實際結果判定——該段沒有任何 R1 問題、也不在 blockers 裡（blockers 要求段落已接受，逐段確認不能代替接受），而且沒有未儲存修改；按下時向 helper 重新讀取並重跑檢查，通過且文字與畫面一致才寫入剪貼簿（比照自介的複製規則）。
  - **自介**：沿用現行規則（jobs-and-messages「投遞自介」）。
- **第二階段（不在現行範圍；Q5＝B）**：104 自動填入（在使用者開著的 104 履歷編輯頁上先列出「欄位、原值、新值」給使用者確認，一次填一段，只填不按儲存）MVP 後、條款查完再另開規格；屆時要改 bridge.md R7 與 plan D7 的文字。
- **驗收**：個人資料各欄複製的內容等於 helper 讀回的已確認值，與畫面不一致時不複製、先更新畫面；客製段落有任何 R1 問題、在 blockers 裡（含只逐段確認、未接受）或有未儲存修改時不能複製。
