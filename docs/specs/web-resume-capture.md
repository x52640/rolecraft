# 求職網站履歷頁擷取（擴充功能）

> 內容搬自已收斂的 `docs/spec-discussions/web-resume-import/spec.md` §5.1（2026-10-12，Codex final2 no_blockers；擁有者裁定見 `plan.md` D28）。W／N／Q 編號對照該討論的 `decisions.md`。
> 權威範圍：履歷頁的頁型登記、觸發、區塊抽取、上限、`submit_resume_capture` 內容與發送者驗證、擷取結果提示。擷取送達 helper 之後的匯入工作階段、AI 整理見 `resume-import.md`；操作清單見 `bridge.md`。

## 前提

- 擷取只在使用者明確觸發時發生（jobs-and-messages F06）；只讀使用者自己開著的那一頁，不取 cookie、不代登入、不在背景開頁或爬多頁。
- 頁面內容是資料不是指令（bridge.md R7）。
- 條款（D28／Q1）：條款明文禁止的網站不開放；查不到明文，擁有者自負風險照樣開放。各站查證結果記在該站 ADR（104：ADR-0004）。
- LinkedIn 只走手動貼上（D8）。
- 照片**不**從網頁抓（要另外取圖、可能帶 cookie）；照片由使用者自己選本機檔（resume-output「照片」）。

## 頁型登記

- 每個支援的網站在 registry 另外登記「履歷頁」：網址規則＋履歷本文根節點的選擇器＋選填的姓名元素選擇器（用途見 resume-import「網頁來源的去個資」）。只讀根節點內，不讀頁首、側欄、推薦職缺、站內訊息等；找不到根節點＝擷取失敗、不送（N3）。
- 網址規則要窄到只符合要讀的那一種頁（符合的頁面點圖示就是擷取、不再開編輯器）。同一站的職缺頁規則與履歷頁規則不得重疊（registry 測試擋），任何網址最多屬於一種頁型。
- 各站實際規則（網址、根節點、姓名元素、讀預覽頁或編輯頁）依該站去識別化 DOM 樣本決定（Q2；建議讀預覽／公開檢視頁），寫進該站 ADR。

## 觸發（D9）

只有這兩種，都是使用者按下才發生：

- **點工具列圖示**：目前分頁網址符合某站的履歷頁規則 → 注入該站的履歷頁擷取腳本（只注入主框架）；其他頁面（含職缺頁、不支援的網站，拿不到分頁或網址時也一樣）照舊開編輯器、不注入。職缺擷取仍只用快捷鍵。
- **快捷鍵 `capture-page`**：依網址決定職缺頁或履歷頁，注入對應的擷取腳本；都不符時沿用現行圖示提示（文字改成「不是支援的職缺頁或履歷頁」），不注入。
- 職缺頁、履歷頁的擷取腳本分開兩支，由 service worker 依網址選（打包方式比照現行 `sites/<platform>.js`），頁面裡不再判斷一次頁型。
- **權限**：不加任何權限。點圖示和快捷鍵一樣會授予 activeTab（離開該網站或關分頁就收回），`chrome.action.onClicked` 收到的分頁物件帶網址，用現有 `scripting` 注入。manifest 仍只有 `activeTab`、`scripting`、`nativeMessaging`，不加 host 權限、`tabs`、`contextMenus`，工具列不改成 popup（現行 manifest 測試照舊通過）。
- **說明文字**：圖示提示文字、擴充功能說明、快捷鍵說明改成講清楚兩種行為（例如圖示：「RoleCraft：在支援的履歷頁點一下擷取，其他頁面開啟編輯器」）。不做依頁面變換的圖示或提示文字（要另加權限）。

### 擷取結果（圖示或快捷鍵觸發都一樣；職缺擷取照現行）

| 情況 | 行為 |
|---|---|
| 擷取成功（helper 回成功，含標了截斷的） | service worker 開一個編輯器分頁（預設頁就是匯入頁），匯入頁顯示 `import.latest_capture`；仍要使用者按「使用這份」才進入核對，也不會呼叫模型。編輯器由 service worker 直接開、不經 helper |
| 找不到本文根節點 | 不送任何東西、不開編輯器；頁面右上角顯示提示（沿用現行頁面內提示：shadow DOM、純文字）：「RoleCraft：這一頁找不到履歷內容（可能不是支援的履歷檢視頁，或網站改版了），沒有擷取或送出任何內容。可以到 RoleCraft 編輯器改用「手動輸入」（在其他分頁點 RoleCraft 圖示開啟）。」 |
| 送出後失敗（helper 連不上、請求被拒或不符 schema） | 不開編輯器；頁面顯示現行的擷取失敗提示，改成指向「手動輸入」 |
| 注入失敗（頁面還沒載入完、瀏覽器不允許注入等） | 不開編輯器；用現行 `showTabNotice` 的徽章與提示文字在圖示上提示（快捷鍵遇到注入失敗也一併改成這樣，不再只寫主控台） |

代價：在履歷頁上點圖示不再開編輯器；擷取失敗時要到其他分頁點圖示才能開編輯器；每點一次就是一次新擷取（helper 記憶體最多 20 筆，resume-import），成功就多開一個編輯器分頁。

## 區塊抽取規則（W1）

依 DOM 順序；同一份 fixture 只能有一種正確輸出。

1. 只讀主框架、根節點內。不讀不渲染的元素（display:none、visibility:hidden、`hidden` 屬性、`aria-hidden="true"`）與 script、style、noscript、template、svg、圖片（含 alt）；不限於目前捲動到的範圍。收合未展開的內容讀不到（不自動展開），各站樣本要記錄這件事。
2. 區塊單位：h1–h6 → 標題（層級＝數字）；li → 清單項（層級＝巢狀深度，超過 6 層一律記 6）；tr → 表格列（儲存格以 Tab 連接）；dt＋dd、只有 th＋td 兩格的列、label＋表單控制項 → 標籤＋值（標籤另存，不算區塊文字）；其他文字以最近的區塊層級祖先為一個段落。每段文字只屬於最近的一個區塊；巢狀的清單、表格各自成區塊，不重複計入外層。
3. 文字取渲染後的文字，連續空白合併成一格；元素內的換行（br 或區塊內換行）切成連續的多個區塊，種類、層級、標籤相同——每個區塊只有一行（W8）。同一元素切出的第二個以後的區塊標 `continues: true`（W18）。
4. 表單控制項：密碼、隱藏、檔案欄位不讀；其他只讀目前值（select 取選中項的文字）。
5. 不送原始 HTML、元素屬性、連結網址。
6. 「可見」與「渲染後的文字、換行」以 Chrome 實際渲染為準（例如 `checkVisibility`、`innerText`）。抽取邏輯把「是否可見、文字與換行」做成可注入的判定：合成 DOM 測試（jsdom 沒有這兩者）注入簡化判定；各站 fixture 存成含樣式的完整頁面，在真實 Chrome 跑（與現有 Chrome 測試同一類，需環境變數）（N6）。

## 上限（W3）

- 區塊數 2,000、全部文字（含標籤）UTF-8 合計 256 KiB（常數定在 contracts）。
- 超過時只送前面放得下的完整區塊並標 `truncated: true`；匯入頁持續顯示「內容不完整」。
- schema 擋超量請求，service worker 不轉送，不會碰到橋接 1 MiB 的協定斷線（helper `MAX_INCOMING_BYTES`）。

## `submit_resume_capture`（content script 白名單操作，相加）

- 內容：`{platform, url, capturedAt, truncated, nameText, blocks: [{kind, level, label, text, continues}]}`。
  - `kind` 是封閉列舉（標題、清單項、表格列、標籤＋值、段落）；`level` 只有標題與清單項有（1–6），其他種類是 null。
  - `nameText`：登記的姓名元素的文字（沒登記或找不到是 null，可以在根節點外），只給 helper 在本機遮蔽與預填，不送模型（W6）。
  - 區塊不帶編號，編號由 helper 依順序配發（b1、b2…），頁面字串不會變成提示的結構（N5）。
  - `url` 只存 origin＋路徑（不存查詢字串與 #），而且必須等於發送頁網址的 origin＋路徑，不符就拒（N4）。網址只存本機、不送模型。
- 成功只回 `{ok: true}`。

## 發送者驗證（操作×頁型，W2）

- `submit_job_capture`、`submit_message_capture` 維持現行：只在職缺頁規則通過時。
- `submit_resume_capture` 只在該站履歷頁規則通過時。兩種規則互不放行。
- 都要主框架、平台與發送頁相符。

## 驗收

- 每個上線網站的履歷頁有去識別化 DOM 樣本 fixture（含樣式的完整頁面）與預期區塊，在真實 Chrome 比對。
- 合成 DOM 測試：巢狀清單、`li` 內含 `p`、隱藏元素、表格、標籤＋值、表單控制項、`br` 換行與 `continues`、找不到根節點、七層清單最內層記 6。
- 網址規則、白名單操作有測試；操作與頁型錯配、`url` 與發送頁不符、非主框架、平台不符被拒。
- 觸發：點圖示時，履歷頁 → 注入履歷頁腳本；職缺頁、不支援的網站、拿不到分頁或網址 → 開編輯器、不注入。快捷鍵：履歷頁、職缺頁各自注入對應腳本，都不符只在圖示提示、不注入。同一站職缺頁與履歷頁規則不重疊。manifest 權限與 popup 照舊。
- 履歷擷取成功開一個編輯器分頁；找不到根節點不送、不開編輯器、頁面提示；送出失敗、注入失敗都不開編輯器。
- 上限：超過時只送完整區塊並標截斷；上限內最大的請求低於 1 MiB。
- 擁有者在真實瀏覽器以自己的 104 履歷頁點圖示實跑一次。
