# ADR-0004 104 職缺頁：條款與 DOM 樣本

- 日期：2026-10-12
- 狀態：進行中（職缺頁條款與 DOM 樣本已完成；履歷頁樣本待擁有者補存）
- 相關：plan.md D16、D20；`docs/specs/jobs-and-messages.md` R10；`docs/specs/open-verifications.md` S10；Task P1-T017
- 樣本：`apps/extension/src/sites/104/fixtures/job-*.html`（4 份，去識別化）

## 證據等級

| 標記 | 意思 |
| --- | --- |
| 【原文】 | 104 公開頁面的原文摘錄，附網址與取得方式 |
| 【樣本】 | 擁有者存下的真實職缺頁上看到的 |

本 ADR 只記錄查到的事實，不判斷條款是否允許 RoleCraft 的做法。

## 1. 條款

### 1.1 會員規約【原文】

- 網址：<https://accounts.104.com.tw/terms>（職缺頁 HTML 裡唯一指向條款的連結，位於 AI 客服的告知文字中；職缺頁頁尾只有「隱私中心」）。
- 標題：「「104 資訊科技集團」會員規約」。頁面上沒有生效或修訂日期。
- 取得方式：2026-10-12 抓取。頁面是前端產生的，內文寫在頁面載入的 `/assets/index-DCxJ8cqA.js` 裡（直接抓網頁只拿到標題）；本節原文從這個檔案取出。

適用範圍（前言）：

> 一零四資訊科技股份有限公司經營之「 104 資訊科技集團」平台以「本平台」簡稱，旗下包含之產品，包括但不限於 104 人力銀行、企業大師、工作世界、高年級、履歷診療室、職涯診所、求職精靈及公司評論…等服務。

第六條「本平台安全維護」：

> (八) 本人同意不得利用非本平台提供之自動化操作工具於本平台服務。
>
> (九) 本人同意不得將本平台提供之內容，自行或使第三人用於人工智慧模型訓練或其他相類行為，或據以開發衍生性產品及服務。
>
> (十) 本人同意若發生違反以上各項約定，經查明屬實者，本平台得視情節輕重限制本人帳號的服務使用權或刪除本人會員資格，並拒絕本人爾後使用本平台各項服務之權利。本平台另可將本人之姓氏、會員代碼或暱稱及事實經過公告於本平台。

第一條（五）會員可行使的權利（跟「自己的資料」有關）：

> 1、得向本平台行使之權利：(1)請求查詢或閱覽。(2)請求製給複製本。(3)請求補充或更正。(4)請求停止蒐集、處理或利用。(5)請求刪除。
>
> 2、 得於本平台自行處理修改密碼、隱私及帳戶設定、修改基本資料、編輯或刪除內容及下載留存於本平台內資訊。

第二條（三）：

> 本條所稱「串連第三方平台或開發商」是指本平台提供之服務內容，可能包含連結到第三方平台或提供由第三方程式開發人員開發之平台應用程式，本人必須自行評估是否要使用此串連服務，對於本人使用此串連服務，本人須自行承擔風險。

查到的範圍內：

- 「自動化操作工具」在規約中沒有定義。
- 規約全文沒有出現「擴充功能」「外掛」「爬蟲」「擷取」等字眼；「瀏覽器」只出現在第一條說明網站伺服器會記錄瀏覽器數值的段落。
- 沒有條文明文提到「使用者以個人擴充功能讀取自己已開啟的職缺頁」，也沒有明文提到「讀取自己的履歷頁」。

### 1.2 沒取得的頁面

| 網址 | 結果 |
| --- | --- |
| <https://www.104.com.tw/info/terms>（會員規約頁的隱私權政策內引用的 `https://104.com.tw/info/terms` 會轉到這裡） | 2026-10-12 自動抓取回 HTTP 403，未取得內容 |
| <https://www.104.com.tw/privacy>（職缺頁頁尾「隱私中心」） | 同上，403 |

這兩頁有沒有相關規範，需要擁有者在瀏覽器打開確認【待手動】。網路搜尋也沒找到其他 104 使用條款原文。

## 2. 職缺頁 DOM 樣本【樣本】

擁有者 2026-10-11～12 在登入狀態用 Chrome「網頁，完整」存下 4 個職缺頁，做成 fixture：

| 檔案 | 職缺 | 大小 |
| --- | --- | --- |
| `job-90x8r.html` | 【客戶成功部】客戶營運經理 Account Manager｜微拓科技 | 30.7 KB |
| `job-8foxb.html` | 客戶成功經理 Customer Success Specialist/Manager｜Bananas PropTech_金啾 | 26.6 KB |
| `job-8zywe.html` | 資深售前解決方案顧問【擴編】｜人易科技 | 28.9 KB |
| `job-8juny.html` | AI專案經理（部分遠端）｜卡米爾 | 33.2 KB |

去識別化做法（原檔每份約 1 MB）：

- 只留 `#app > .app` 底下含 `.job-header` 的區塊（麵包屑、職缺標題列、`.col.main` 主欄）；整個頁首（含登入者姓名、email、My104 選單）不保留。
- 移除：`script`（JSON-LD 只留 JobPosting，且只留公開欄位）、`style`、`link`、圖片／svg／iframe、註解、廣告自訂元素、翻譯工具、側欄（瀏覽紀錄、履歷符合度、相似職缺）、推薦職缺、公司環境照片、分享／檢舉工具列、AI 客服、頁尾。
- 屬性只留 `class`、`id`、`href`、`type`、`lang`；`data-*`（含 `data-gtm-*` 追蹤）、`style` 全刪；`href` 去掉 query（`jobsource` 等）。
- 「聯絡方式」的聯絡人姓名換成「（聯絡人已去識別化）」。公司公開的職缺內容保留。
- 職缺內容區加 `<!-- prettier-ignore -->`，保留原頁空白，`textContent` 才和真實頁相同。

確認方式：

- 以擁有者姓名、email 帳號、`gmail`、`My104`、`登出`、`應徵紀錄`、`jobsource`、`gtm`、聯絡人原名等字串搜尋 4 份 fixture，皆 0 筆（檔頭說明註解裡的「瀏覽紀錄」字樣除外）；也搜尋 email 格式與手機號碼格式，0 筆。
- 用同一組定位方式分別讀原檔與 fixture，下表各欄位文字逐字相同（4/4）。

## 3. R10 欄位定位

R10 必要欄位：公司、職稱、職缺描述本文。下表也列 `jobs-and-messages.md` F 段提到的其他欄位。「4 樣本」欄是同一個定位方式在 4 份樣本都找得到、而且文字和原頁相同。

| 欄位 | R10 | 定位方式 | 4 樣本 |
| --- | --- | --- | --- |
| 公司 | 必要 | `.job-header__title .mt-3 > a:first-child` 的文字。另有兩個來源文字相同：JSON-LD JobPosting `hiringOrganization.name`、麵包屑 `.breadcrumb-list__item` 第 2 項 | 一致 |
| 職稱 | 必要 | `.job-header__title h1`。另有 JSON-LD `title`、麵包屑第 3 項 | 一致 |
| 職缺描述本文 | 必要 | `.job-description .job-description__content`（`p`，換行是文字裡的換行字元，要用 `textContent`）。JSON-LD `description` 是跳脫過的 HTML 字串（含 `&lt;br&gt;`、多一個「【工作內容】」標題），和 DOM 文字不同 | 一致 |
| 職責 | 選用 | 104 沒有獨立欄位，寫在職缺描述本文裡 | — |
| 必要條件 | 選用 | `.job-requirement-table .list-row`：`.list-row__head` 文字（工作經歷、學歷要求、科系要求、語文條件、擅長工具、工作技能）對應 `.list-row__data` | 一致（6 列都在） |
| 加分條件 | 選用 | 104 沒有名為「加分條件」的欄位。最接近的是「其他條件」：`.job-requirement.col .list-row` 中 head 為「其他條件」的那列；沒填時值是「未填寫」 | 結構一致；3 份是「未填寫」 |
| 地點 | 選用 | `.job-description-table .job-address`（第 1 個 `span` 是地址；`span.t4` 捷運距離不一定有）。JSON-LD `jobLocation.address` 也有 | 一致 |
| 待遇 | （F 段未列） | `.job-description-table .list-row` head「工作待遇」 | 一致 |
| 來源 URL | 記錄用 | 執行時的網址；`link[rel=canonical]` 是不帶 query 的 `https://www.104.com.tw/job/<id>` | 一致 |
| 擷取時間 | 記錄用 | 擷取當下時間，不從頁面取 | — |

跨樣本差異（定位時要避開）：

- `.job-header__cont`、`is-fixed` 會隨捲動狀態換到不同元素上（`job-8foxb` 是固定標題列狀態），不能拿來定位。
- `.job-requirement.col` 帶 `opened`／`is-ellipsis` 等展開狀態 class；`job-8foxb` 的「其他條件」是收合狀態（`is-ellipsis`，有「顯示全部」按鈕），但 DOM 裡已有文字。
- 2 份樣本在條件區多一個「歡迎所有求職者…」區塊（`.job-requirement.col`，沒有 `.list-row`）。
- Vue 的 `data-v-*` 屬性是建置雜湊，fixture 已移除，定位不可依賴。

## 4. 投遞能否附自訂 PDF（D20）

- 樣本看得到的：職缺標題列有「應徵」按鈕（`.apply-button`）；樣本頁的推薦職缺元件上帶有 `applyurl="//www.104.com.tw/jobs/apply/form"`，表示應徵在另一個頁面進行。
- 4 份樣本整頁搜尋「附件」「上傳」「附加」「PDF」「應徵信」「求職信」皆 0 筆。
- 結論：應徵表單頁不在樣本內，看不出能不能附自訂 PDF。**需擁有者實際操作確認**【待手動】：點「應徵」後的表單能否選／上傳自己的 PDF 履歷或附件。

## 5. 履歷頁（待補）

擁有者還在補存自己 104 履歷頁的樣本；履歷頁的 DOM 定位與去識別化 fixture 待補。條款部分見 1.1（沒有明文提到讀取自己的履歷頁）。

## 殘餘

- `www.104.com.tw/info/terms`、`www.104.com.tw/privacy` 未取得（403）【待手動】。
- 投遞流程能否附自訂 PDF【待手動】。
- 4 份樣本都是同一天、同一種版面（台北市、全職）；其他版面（例如派遣、海外、已關閉職缺）沒有樣本。
- 履歷頁樣本待補。
